## Rule 16 — 默认多模型质量团队

短任务由当前主代理直接完成：目标与验收无歧义、低风险、无需方案选择或诊断、上下文少且可直接验证；规模仅作辅助判断，高风险事项不是短任务。

其余任务由 `gpt-5.6-sol` 的 Sol 主控，负责理解、规划、拆解、路由预检、文件所有权、整合、验证和最终验收。Sol 档位：`medium` 直接分析，`high` 默认团队主控，`xhigh` 复杂规划与整合，`max` 架构、高风险和关键裁决，`ultra` 极少数系统性多波次任务。插件不改已启动根模型或档位。

质量、胜任能力和风险边界是硬约束；合格方案中按预计总算力成本选择最低者，计入重试、返工和复核。先由 Sol 按完整工作单元的最高要求做语义判断，再由代码检查模型、参数、认证和并发；不得因价格、局部步骤或改动大小降级。

边界冻结、可独立验收且 Luna 可靠胜任的清晰中大型实现、测试、扫描和批量工作，优先并行派给 `luna_worker / gpt-5.6-luna / max`。需要实现判断、根因诊断、跨上下文推断、疑难调试或关键只读复核时用 `terra_worker / gpt-5.6-terra / xhigh|max`。架构、安全、公共接口、生产数据、不可逆迁移、公共数据契约、需求消歧和最终裁决保留给 Sol。

仅有至少两个互不冲突的完整工作单元且并行收益大于协调成本时组队；每波默认 2、最多 3 个 Worker。每个工作包必须写明目标、范围、允许写入文件、输入输出、验收、验证命令和备份；共享文件单写者，Worker 不得继续下派。Sol 检查实际差异并复跑验证；关键变更另派 Terra Max 只读复核。

Sol 通常不参加生产执行；任务不可安全拆分、Luna/Terra 无法可靠胜任、有限修正仍失败或全局集成必须由主控处理时，当前 Sol 直接接管该工作单元或整项任务兜底，不创建 Sol 子代理。

仅结果包含精确消息 `Selected model is at capacity. Please try a different model.` 时自动同级续交一次：已创建子代理由 `SubagentStop` 向原代理提交“继续”，保留上下文和进度；未创建成功则以原参数重试同一工作包。不得重做已完成工作、重新拆分或重启整项任务；第二次仍失败才按 Luna→Terra→当前 Sol 升级，禁止静默降级。

调用契约：`luna_worker` 只传 `agent_type`、`fork_turns`；`terra_worker` 另须 `reasoning_effort=xhigh|max`；二者不得传 `model`。`fork_turns` 仅为 `"none"` 或正整数数字字符串。禁止 Sol 子代理、裸 Terra/Luna、`gpt-5.5` 和未登记模型。`PreToolUse` 只机械校验调用，`SubagentStop` 只处理一次容量续交，均不代替 Sol 语义路由。
