# 路由矩阵

## 核心原则

当前 `gpt-5.6-sol` 是唯一主控，负责理解、拆解、分派、整合、验收和兜底。插件保留任务启动时已经选择的 Sol 推理档位，不在运行中替用户切换根档位。

选择路线时按下面的顺序判断：

1. 短任务或强耦合工作留给当前 Sol。
2. Luna Max 能可靠完成的低判断、可机械验证单元，直接使用 Luna，不升级到更贵路线。
3. Luna 不适合时，边界清楚、需要适度判断、适合独立下派的单元优先 Sol Medium。
4. 耦合、顺序执行或下派没有净收益的工作留给当前 Sol。
5. Terra 只有在具体任务上相对合格的 Sol 路线有明确优势时使用，并选择最低可靠档位。
6. 关键高风险改动需要独立性时，增加一次 Sol Reviewer 只读复审。
7. 所有结果都由当前 Sol 检查实际改动、重跑必要验证并最终裁决。

## 主控档位

| 根档位 | 合理用途 |
|---|---|
| `medium` | 常规规划、拆解、整合和边界清楚的直接工作 |
| `high` | 需要更细致检查，但不需要复杂推理升级的工作 |
| `xhigh` | 复杂规划、跨模块整合和严格验收 |
| `max` | 疑难、高风险、架构和关键裁决 |
| `ultra` | 系统性、超复杂长任务，不作为日常默认 |

## Worker 选择

| 代理 | 固定模型 | 档位 | 使用条件 |
|---|---|---|---|
| `luna_worker` | `gpt-5.6-luna` | `max` | 决策冻结、判断负荷低、可机械验证且能可靠完成；满足时第一优先 |
| `sol_medium_worker` | `gpt-5.6-sol` | `medium` | 边界清楚、需要适度判断、可独立验收，且下派或并行有净收益 |
| `terra_worker` | `gpt-5.6-terra` | `xhigh` / `max` / `ultra` | 对具体工作单元有明确任务优势；选择最低可靠档位 |
| `sol_reviewer` | `gpt-5.6-sol` | `xhigh` | 关键高风险变更的一次独立只读复审 |

Worker 必须留在工作包范围内，不做无关修改。普通模式下 Worker 不再下派；Super mode 下只有工作包明确授权且深度小于 `d4` 才能继续拆分。共享文件始终只有一个写入者。

## 质量与成本

- 质量门槛先决定“哪些路线能可靠完成”，价格只在合格路线之间比较。
- Luna 符合条件时直接选择，不读取外部评测数据。
- 多个 Sol / Terra 路线都能胜任且确实难选时，一个根任务最多读取一次本地 Radar 摘要。IQ 差小于 3 时优先保留当前热模型或原代理，再比较预计总成本。
- 路由确定后冻结，不为微小价格差反复切换。只有工作单元、边界、可用性或结果变化时才重判。
- Terra 不是固定升级层，深推理也不是自动选择 Terra 的理由。

## 并行与等待

普通模式默认从一个 Worker 开始，仅在工作单元互不依赖、写入不冲突且并行收益高于协调成本时增加并发。大量同类工作先验收一个代表性单元，再填充宿主的实际可用容量；完成一个再补充一个。

Super mode 支持 `d1-d4` 和最多 25 个子线程，`d4` 不再下派。25 是插件允许的上限，不保证宿主同时提供 25 个槽位。Worker 运行时使用一次长阻塞等待，由结果提前唤醒，不主动短轮询。

## 调用契约

```text
luna_worker: agent_type + task_name(luna_max__unit) + fork_turns
sol_medium_worker: agent_type + task_name(sol_medium__unit) + fork_turns
terra_worker: agent_type + reasoning_effort(xhigh|max|ultra) + task_name(terra_<effort>__unit) + fork_turns
sol_reviewer: agent_type + task_name(sol_reviewer_xhigh__unit) + fork_turns
```

具名代理不传 `model`。默认 `fork_turns:"none"`，只有确实需要少量历史时才使用正整数字符串。每个工作包必须包含目标、范围与所有权、可观察验收标准，以及“失败回当前 Sol、保留已完成工作”的兜底说明。

## 容量恢复

子代理精确返回选定模型容量错误时，在同一上下文续交一次；第二次仍失败就交回当前 Sol。不得重启整个任务、重做已完成工作，也不得把能力或质量失败按容量错误处理。当前 Hook 只能处理 `SubagentStop`，不能替主控自动恢复容量通知。
